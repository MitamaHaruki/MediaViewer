# Phase 4 検証報告（ファイル形式の変換）

- 実施日：2026-10-20
- 対象：開発指示書 §9（ファイル形式の変換）、§16 Phase 4、仕様決定事項（FFmpeg は必要な機能だけの自前ビルドを同梱）
- 検証環境：Phase 1〜3 と同じ。FFmpeg は開発用に公式配布の GPL 版（9.0）を使用

## 1. 実施内容

### 変換画面（§9.1）

- 「ファイル → 変換...」で別ウィンドウを開く。変換中もビューワーは操作できる。
- 表示は「入力ファイル」「出力形式」「保存先フォルダ」「ファイル名」「変換開始／キャンセル」「進捗」と、変換前の確認事項のみ。
- 保存先の初期値は元ファイルと同じフォルダ、ファイル名は拡張子だけを変えたもの。
- 同名のファイルがあるときは「上書き／連番で保存／キャンセル」を選ぶ。元ファイルと同じ場所・名前は自動で連番にし、元ファイルは決して上書きしない。
- 変換中にウィンドウを閉じようとすると、中止するか確認する。完了後は「フォルダを開く」「ビューワーで開く」が使える。

### 動画・音声（§9.2）

| 項目 | 内容 |
|---|---|
| 調査 | ffprobe でストリーム構成・コーデック・時間長・言語・アルバムアートを調べる |
| コピー優先 | 出力形式が扱えるコーデックは再エンコードしない（例：MKV→MP4 で H.264・AAC・Opus・FLAC はそのままコピー） |
| 必要なときだけ変換 | MP4／MOV／AVI：H.264（CRF 18）＋AAC 256k（AVI は MP3）、WebM：VP9＋Opus、MP3：LAME（VBR 品質2）、M4A：AAC、OGG：Vorbis、FLAC／WAV：可逆 |
| 音声トラック | 出力形式が扱える限りすべて残す（言語・タイトルも引き継ぐ）。音声形式は最初のトラックのみで、事前に通知 |
| 字幕 | MKV はコピー、MP4／MOV は mov_text、WebM は WebVTT へ変換。画像字幕や書式の欠落は事前に通知 |
| 添付・アルバムアート | フォント等の添付は MKV のみ保持。アルバムアートは MP3／FLAC／M4A で保持、それ以外は通知 |
| その他 | メタデータ・チャプターの引き継ぎ、MP4 系はストリーミング向けの配置（faststart）、WAV は元の量子化ビット数（16／24bit）に合わせる |

### 画像（§9.2、§5.2-8）

| 項目 | 内容 |
|---|---|
| 出力形式 | PNG・JPEG（品質92）・BMP・GIF・TIFF（LZW）は WIC、WebP は FFmpeg（libwebp）。可逆の元画像からは可逆の WebP にする |
| ICC | PNG・JPEG・TIFF・WebP には埋め込む（WebP は自前で ICCP チャンクを追加）。BMP・GIF は sRGB の画素に変換して通知 |
| 色指定の引き継ぎ | EXIF の Adobe RGB 指定や PNG の cICP・gAMA/cHRM・グレーICC は、同等の ICC として埋め込む |
| CMYK | JPEG・TIFF は CMYK のまま保持。RGB 形式へは Display P3（ICC 非対応形式は sRGB）に変換して通知 |
| EXIF の向き | 画素に反映して保存し、向き情報は書かない（二重に回転しない） |
| 透過 | JPEG・BMP は白で合成し事前に通知。GIF は透明を保ち、半透明と減色（256色）を通知 |
| その他 | 16bit は PNG・TIFF で保持し、他は 8bit にすることを通知。撮影日時・カメラ情報などのメタデータを引き継ぐ。複数フレームは最初のフレームのみと通知。HDR 画像の変換は未対応として断る |

### 処理の安全性（§9.3）

- 一時ファイル（`~名前.converting-xxxx.拡張子`）に書き、出力を読み戻して確認してから最終名に置き換える。失敗・キャンセル時は一時ファイルを消す。
- 動画・音声の確認：期待した映像・音声のストリームがあり、長さが元の9割以上であること。画像の確認：読み戻せて、寸法が正しいこと。
- FFmpeg の引数は1要素ずつ渡し、ファイル名をシェル文字列へ連結しない。FFmpeg は変換中だけ起動し、優先度を下げて実行する。
- キャンセルは FFmpeg に終了を指示し、3秒で終わらなければプロセスごと強制終了する。
- エラーは日本語で表示し、FFmpeg のエラー出力はログに記録する。

## 2. テスト

単体テスト 101 件（Phase 3 から 40 件追加）がすべて成功。

- 変換手順の決定：コピーと再エンコードの判定、ストリームごとの指定、音声トラック・字幕・添付・アルバムアートの扱いと通知、WAV のビット数、種類の合わない変換の拒否、ファイル名をそのまま引数に渡すこと
- ffprobe の出力の読み取り、進捗の読み取り、出力名（拡張子の変更・連番・同一ファイル判定・一時ファイル）
- 実際の FFmpeg での変換：MKV（音声3本＋字幕）→MP4 は再エンコードなしで全トラックと言語を保持、→WebM は VP9／Opus／WebVTT に変換、MP3→FLAC でアルバムアートを保持、キャンセルで出力も一時ファイルも残らない（3秒以内）、元ファイルへの上書きを拒否、壊れたファイルは日本語のエラー
- 画像：ICC の埋め込み（JPEG／TIFF）、BMP で sRGB へ正しく変換、JPEG での白合成、GIF の透明、EXIF の向き7種類すべてで表示と同じ向き、CMYK の保持と Display P3 への変換、WebP への ICC 埋め込みと可逆・透過、カメラ情報の引き継ぎ、元ファイルへの上書きの拒否

アプリでの確認：変換画面を開き、MKV→MP4（0.9秒、再エンコードなし、音声3本と言語を保持）を実行。WebM を選ぶと再エンコードの通知が出ることを確認。

## 3. 自前ビルドの FFmpeg に含める機能（Phase 5 で GitHub Actions によりビルド）

| 区分 | 含めるもの |
|---|---|
| プログラム | ffmpeg、ffprobe（共有ライブラリ構成にして重複をなくす） |
| 読み込み | デマルチプレクサー・デコーダーは原則すべて（再生できるファイルは変換もできるように）。AV1 は dav1d |
| エンコーダー | libx264（GPL）、libvpx-vp9、aac、libopus、libmp3lame、libvorbis、flac、pcm 系、mov_text、webvtt、libwebp |
| 書き出し | mp4、mov、ipod（m4a）、matroska、webm、avi、mp3、wav、flac、ogg、webp |
| フィルター | 拡大縮小・形式変換・リサンプル・回転（向きの自動補正用）など最小限 |
| 外部ライブラリ | x264、libvpx、opus、lame、vorbis/ogg、libwebp、dav1d、zlib、bzip2 |
| 除外 | ネットワーク（file と pipe 以外のプロトコル）、デバイス入出力、ハードウェア固有の拡張、不要なフィルター |

想定サイズは 30〜50 MB（公式版は ffmpeg.exe と ffprobe.exe で約330 MB）。

## 4. 既知の制約

| 項目 | 内容 |
|---|---|
| 配布用の FFmpeg | 現在は開発用に公式版を参照（アプリと同じ場所の `ffmpeg` フォルダ → 環境変数 `MEDIAVIEWER_FFMPEG_DIR` → リポジトリの `tools/ffmpeg-dl` の順に探す）。自前ビルドと同梱は Phase 5 |
| 種類をまたぐ変換 | 動画→音声の抽出、画像→動画などは初期版の対象外（仕様 §9.2） |
| HDR | HDR 画像・HDR 動画のトーンマップ変換は未対応（HDR 画像は変換を断る。HDR 動画を H.264 にすると色が正しく変換されない可能性がある） |
| WebP の大きさ | 16383 ピクセルを超える画像は WebP に保存できない（形式の制約） |
| 複数ファイルの一括変換 | 初期版では必須でないため未対応（仕様 §9.1） |

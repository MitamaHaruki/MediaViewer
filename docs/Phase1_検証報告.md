# Phase 1 検証報告（動く最小UIと技術検証）

- 実施日：2026-10-20
- 対象：開発指示書 §16 Phase 1、仕様決定事項 D1・D2・D2a
- 検証環境：Windows 11（ビルド 26300）、Intel Core i9-12900F（24スレッド）、NVIDIA GeForce RTX 4060 Ti、1920×1080 モニター3台（いずれもSDR・ICC未設定＝既定のsRGB）

## 1. 結論

WinUI 3 で、仕様の重要要件を満たす描画方式が成立することを確認した。

- 画像と動画を **同じ Direct3D 11 のスワップチェーン（FP16 scRGB）** に描画し、拡大縮小・移動を同じロジックで扱える。
- 動画の上に操作UIを普通に重ねられる（Airspace問題なし）。フルスクリーンでも操作バーが映像の背後に隠れない。
- 広色域画像（Display P3／Adobe RGB）は sRGB に丸めず、scRGB のまま出力できる（色変換の数値テストで確認）。
- 再生・ズーム時のCPU負荷は低い（下表）。

## 2. 採用した方式

| 項目 | 方式 |
|---|---|
| UI | WinUI 3（Windows App SDK 2.x、非パッケージ・自己完結） |
| 画像デコード | WIC。8bit は BGRA8、高ビット深度は FP16 のまま GPU へ転送し、CPU側のデコード結果は転送後に解放 |
| 色変換 | Direct2D の ColorManagement エフェクト（レンダリング意図は相対的な色域維持で固定）。中間バッファは 32bit 浮動小数 |
| 出力 | FP16 scRGB のスワップチェーン（SwapChainPanel）。HDR・自動色管理時は scRGB のまま OS に渡し（二重変換なし）、HDR では SDR 白レベルへ補正。SDR 時はモニターICCへ変換した値を出力 |
| 動画・音声 | Windows の MediaPlayer ＋ FFmpegInteropX（FFmpeg 8.1 でデコード、対応コーデックはハードウェアデコード）。フレームサーバーモードで GPU テクスチャへ直接コピーし、画像と同じ経路で描画（CPUへの読み戻しなし） |
| 表示倍率・移動 | `ViewportController`（Core）で画像・動画共通 |

## 3. 計測結果

Release 発行版（自己完結・トリミング・ReadyToRun）での値。CPU 使用率は全24スレッドに対する割合。

| 項目 | 結果 | 目標（仕様 §11.2） |
|---|---|---|
| 起動（ウィンドウ表示まで） | 初回 1.35 秒、2回目以降 約0.26 秒 | 3 秒以内 |
| 何も開いていないときのCPU | 0.00〜0.01% | 概ね 1% 以下 |
| 何も開いていないときのメモリ（Private） | 約 91 MB | — |
| 1080p30 H.264 再生中のCPU | 0.35%（Debug版） | — |
| 4K60 H.264 再生中のCPU | 0.83%（メモリ 約351 MB） | 対応HWで滑らか |
| 4K60 再生中にホイール拡大・ドラッグ移動 | 0.69%、再生は止まらない | 一時停止させない |
| 8000×6000 画像 | 表示可、メモリ 約335 MB | — |
| 発行サイズ | 133 MB（うち FFmpeg 約47 MB） | — |

## 4. 動作確認した項目

- 画像：ICC付きPNG/JPEG、透過PNG、巨大画像、フィット表示（小さい画像は等倍上限）
- 色変換の数値テスト（34件中、色関連9件）：Display P3・Adobe RGB の ICC 付き画像、ICCなし（sRGB扱い）、HDR の白レベル補正、SDR のモニターICC変換、ICC取得不可時のフォールバック、壊れたICCのフォールバック
- 動画：読込み時の自動再生、終端で最終フレームを表示したまま停止（次へ進まない・リピートしない）、再生ボタンで先頭から再生、回転メタデータ付き動画（MP4）の回転表示
- 音声：アルバムアート＋ファイル名、アートなしは音符アイコン
- 複数音声トラック：ファイル内で最初のトラックを選択（ファイル側の既定指定より優先）、名前・言語・コーデック・チャンネル数のうち取得できたものだけ表示
- 前後移動：自然順、種類をまたいだ移動、先頭・末尾で循環しない
- フルスクリーン：現在のモニターを覆う、操作バーが重なって表示され約5秒で自動非表示、Esc で元の位置・サイズに復元
- 「このアプリについて」：開発者表記とアカウントURLが指定どおり表示される
- 3台のモニター間の移動で表示先情報が更新される（今回の環境は3台とも SDR・sRGB）

## 5. 既知の制約・未確認事項

| 項目 | 内容 | 対応予定 |
|---|---|---|
| タッチ操作 | ピンチ・スワイプ・ダブルタップは実装済みだが、この環境ではタッチ注入が WinUI に届かず未検証 | タッチ対応機での実機確認が必要 |
| HDR／自動色管理の実機表示 | 数値テストのみ。今回のモニターは HDR・ACM を使っていない | HDR／ACM 対応モニターで確認 |
| SDR のモニターICC経路 | 数値テストのみ（今回のモニターはICC未設定） | ICC を設定したモニターで確認 |
| CMYK 画像 | 未対応（エラー表示） | Phase 2 |
| GIF/WebP アニメ、TIFF 複数ページ | 最初のフレームのみ（仕様決定事項 #10） | — |
| MKV の回転情報 | Windows のプロパティから取得できないため未対応（MP4/MOV は対応） | 必要なら FFmpeg 側から取得 |
| 巨大画像のメモリ | 8000×6000 で約335 MB。表示サイズに応じた縮小保持で削減余地あり | Phase 2 |
| GPU デバイス消失 | 描画失敗時に落ちないが、デバイスの作り直しは未実装 | Phase 2 |
| ドラッグ＆ドロップ | 実装済み、自動テストは未実施 | 手動確認 |
| 設定の保存（音量・フィルター・ウィンドウ位置） | 未実装 | Phase 3 |
| Native AOT | 未試行（起動時間は目標を満たしている） | 必要に応じて |
| トリミング警告 | WinRT・Windows SDK・SharpGen で IL2104 警告。発行版で画像・動画・音声の動作は確認済み | 継続監視 |
